# FaHrService 产品文档

> 版本：v1.0 ｜ 更新日期：2026-10-12

## 一、产品概述

FaHrService 是门店招聘管理系统，由两个相互独立但共享数据的子系统组成：

| 系统 | 定位 | 访问地址 |
|---|---|---|
| **FaHrService 管理系统（HRS）** | 内部管理后台：人员档案、组织架构、账号与权限管理 | https://fahr.nickhome.cloud/ |
| **电子简历系统** | 简历浏览与招聘流程推进：约面、面试、入职确认 | https://resume.nickhome.cloud/ |

两个系统共用同一套账号体系和数据库，数据实时同步：

```
                ┌─────────────────────────────┐
                │   FaHrService 后端（共用）    │
                │   Node.js + Prisma + SQLite  │
                └──────────────┬───────────────┘
                               │
            ┌──────────────────┴──────────────────┐
            ▼                                     ▼
  fahr.nickhome.cloud                 resume.nickhome.cloud
  人员档案 / 品牌管理 / 用户权限        简历浏览 / 流程操作
  面向：管理员、FaHr                   面向：管理员、FaHr、店长、客户HR
```

**核心流转**：HRS 录入人员 → 发布 → 电子简历系统可见 → 约面确认 → 面试结果 → 入职确认。

## 二、角色与权限

系统内置 4 种角色：

| 角色 | HRS 管理系统 | 电子简历系统 |
|---|---|---|
| **管理员** | 全部权限（含用户管理、权限分配） | 全部操作 |
| **FaHr** | 除「用户管理」外全部权限 | 全部操作 |
| **店长** | 无权限（访问时引导至简历系统） | 浏览 + 约面确认 + 面试结果 |
| **客户HR** | 无权限（访问时引导至简历系统） | 仅浏览，只读 |

### 数据权限（按店铺范围分配）

- 非管理员账号需在「用户管理 → 分配权限」中勾选可管辖的**品牌 / 城市 / 店铺**（勾品牌 = 其下全部城市店铺，勾城市 = 其下全部店铺，也可精确到单店）
- 范围实时生效，未分配范围的账号看不到任何数据
- 所有接口在服务端强制校验范围，越权访问/操作一律被拒绝
- 店长、客户HR 额外受「仅可见已发布人员」限制

## 三、FaHrService 管理系统（HRS）

### 3.1 登录

- 地址：https://fahr.nickhome.cloud/
- 店长 / 客户HR 账号登录后会自动引导至电子简历系统；直接访问 HRS 会看到无权限提示页，可一键退出切换账号
- 会话有效期 7 天，右上角可修改密码

### 3.2 人员管理

**搜索筛选**（可组合，点「搜索」生效，支持回车）：

- 姓名关键词（模糊匹配）
- 品牌 / 城市 / 店铺（级联选择）
- 招聘状态（待约面 / 已接受约面 / 已拒绝约面 / 面试通过 / 面试未通过 / 已确认入职 / 已拒绝入职）
- 发布状态（已发布 / 未发布）
- 更新时间（日期区间）

**列表**：照片、姓名、性别、年龄、品牌、城市、店铺、可面试时间、备注、状态、更新时间；表头固定，内容区滚动，支持分页（10/20/50 条）。

**单条操作**：

| 操作 | 说明 |
|---|---|
| 发布 | 将人员简历发布到电子简历系统（确认后生效，不可重复发布） |
| 取消发布 | 从电子简历系统下线该人员 |
| 编辑 | 未发布人员可编辑全部信息 |
| 预览 | 已发布人员信息锁定，只能只读预览 |
| 删除 | 删除人员（含其简历，不可恢复） |

**批量操作**：勾选表格首列后，工具栏出现「批量发布 / 批量删除」；批量发布自动跳过已发布人员，均有二次确认。

**人员档案字段**：照片（JPG/PNG/GIF/WebP，≤10MB）、姓名（必填）、性别、年龄、电话、所属店铺（必填）、工作经历（公司/起止月份/工作内容，可多条）、可面试时间（时间段，可多条）、备注。

### 3.3 品牌管理

- 品牌 → 城市 → 店铺 三级组织树的增删改
- 删除保护：品牌下有城市、城市下有店铺、店铺下有人员时禁止删除
- 同名查重（同层级下不允许重名）

### 3.4 用户管理（仅管理员）

- 创建用户：用户名 + 密码（≥6 位）+ 角色
- 编辑用户：调整角色、重置密码
- 分配权限：树形勾选品牌/城市/店铺，控制数据可见与可操作范围
- 删除用户：不能删除当前登录账号；系统至少保留一个管理员
- 默认管理员账号：`admin / admin123`（**请尽快修改密码**）

## 四、电子简历系统

### 4.1 登录

- 地址：https://resume.nickhome.cloud/
- 与 HRS 共用账号；所有角色均可登录，店长/客户HR 数据自动收窄到授权范围

### 4.2 简历浏览

- 左侧**店铺清单**：品牌/城市/店铺树，店铺带已发布人数角标，点任意节点筛选
- 右侧**人员卡片**：照片（点击放大预览）、姓名、性别年龄、状态标签，分页展示
- 仅显示「已发布」人员

### 4.3 简历详情与流程操作

点「详情」打开简历弹窗：头像（点击放大）、个人信息、应聘门店、流程步骤条、工作经历、备注、当前状态。

**流程操作按状态出现**（均有二次确认）：

| 当前状态 | 可用操作 | 可操作角色 |
|---|---|---|
| 待约面 | 选择面试时间 → 确认约面 / 拒绝约面 | 管理员、FaHr、店长 |
| 已拒绝约面 | 重新选择时间约面 | 管理员、FaHr、店长 |
| 已接受约面 | 面试通过 / 面试未通过 | 管理员、FaHr、店长 |
| 面试通过 | 确认入职 / 放弃入职 | 管理员、FaHr |
| 任意状态 | 重置招聘流程（回到待约面） | 管理员、FaHr |

**状态机**：

```
待约面 ──确认约面──▶ 已接受约面 ──通过──▶ 面试通过 ──确认入职──▶ 已确认入职
   │                    │                    │
   └──拒绝约面──▶ 已拒绝约面      └──未通过──▶ 面试未通过   └──放弃──▶ 已拒绝入职
                        │
   任意状态 ──重置──▶ 待约面 ◀──重新约面──┘
```

## 五、技术架构

| 层 | 技术 |
|---|---|
| 前端 | Vue 3 + Element Plus + vue-router + Vite（两个系统各自独立构建部署） |
| 后端 | Node.js + Express + tsx（单服务双站点共用，端口 5000） |
| 数据库 | SQLite（Prisma ORM），文件：`prisma/dev.db` |
| 部署 | Nginx 静态托管 + 反代，Let's Encrypt 证书（DNS-01），systemd 守护（fahrs.service） |
| 代码 | [FaHrService](https://github.com/nickw116/FaHrService) ｜ [resume-browser](https://github.com/nickw116/resume-browser) |

**安全机制**：scrypt 密码加盐哈希、Bearer Token 会话（7 天）、接口级角色鉴权、服务端数据范围过滤、照片上传类型/大小校验、发布状态编辑锁。

## 六、运维说明

```bash
# 重启后端
sudo systemctl restart fahrs

# 部署 HRS 前端
cd /home/ubuntu/FaHrService/web && npm run build
sudo rsync -a --delete dist/ /var/www/fahr/

# 部署电子简历前端
cd /home/ubuntu/resume-browser && npm run build
sudo rsync -a --delete dist/ /var/www/resume/

# 数据库结构变更
cd /home/ubuntu/FaHrService && npx prisma db push
```

## 七、常见问题

**Q：首次打开域名显示「无法访问」，刷新几次才好？**
A：域名 ICP 备案审核中，腾讯云对未备案域名做抽样拦截。备案通过后自动解除。期间可多次刷新，或使用 Cloudflare 代理方案过渡。

**Q：为什么店长登录 HRS 看不到内容？**
A：店长角色仅可使用电子简历系统，访问 HRS 会显示无权限提示页，可切换账号或前往简历系统。

**Q：新建账号为什么看不到任何人员？**
A：非管理员账号需要管理员在「用户管理 → 分配权限」中分配品牌/城市/店铺后才可见对应数据。

**Q：已发布人员为什么不能编辑？**
A：为保证对外展示的简历信息一致，发布后信息锁定。先「取消发布」→ 编辑 → 重新发布即可。
